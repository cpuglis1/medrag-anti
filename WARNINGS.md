# ⚠️ WARNINGS — READ BEFORE USING OR CITING THIS CODE

This file is deliberately the loudest document in the repo. The system reconstructed
here produces **medical-sounding text** and reports **headline accuracy numbers** that
are easy to misread. Both facts carry real risk. Read this before running anything,
and before repeating any claim from the paper.

---

## 1. This is a RECONSTRUCTION, not the original code

The original implementation behind the paper
*"Dynamic Adapter Swapping and Retrieval-Augmented Generation for Stochastic Parroting
Reduction in Large Language Models"* (Puglisi, JHU, May 2024) was never committed to any
surviving repository. The only published artifact is the early retrieval-only snapshot at
`github.com/cpuglis1/MedRAG-Anti-Stochastic-Parroting` (3 files, frozen 2024-03-04).

**This scaffold was rebuilt from the text of the paper.** Function signatures, thresholds,
and control flow are faithful to what the paper *describes*, but:

- Numbers the paper does not state (e.g. the cosine threshold `t`, exact LoRA rank, learning
  rate, per-category sample counts) are **guesses marked `PAPER UNSPECIFIED`** in
  `configs/default.yaml`.
- The model/data code (MLX + Torch backends, BioMedLM embedder, FAISS KB build, QLoRA
  training, dataset loaders) is now **fully implemented, but has NOT been executed
  end-to-end** in this environment — Llama-2 is gated and the full run needs ~18 GB of
  downloads plus hours of on-device compute. It is written against the `mlx-lm` /
  `transformers` / `datasets` / `faiss` APIs **as of early 2026**; those APIs shift between
  releases, so **pin your versions** and expect to adjust a call or two on first run. Treat
  the first successful end-to-end run as the real validation — do not assume these reproduce
  the paper's numbers until you have run them and checked the output yourself.
- The Hugging Face dataset ids/field names for Med-HALT are marked `VERIFY` in
  `evaluation/datasets.py` and fail loudly (not silently) if they don't match.

---

## 2. NOT FOR CLINICAL, DIAGNOSTIC, OR PATIENT USE

This is a **research proof-of-concept**. It is not a medical device, has no regulatory
clearance, and was never validated against clinical outcomes. Its outputs:

- are generated by a **7B model** that scored **at chance on real medical knowledge**
  (see §3), and
- retrieve from a static 2024 PubMed snapshot with **unvalidated recall** (precision was
  estimated at 72% by a single lay reviewer over 50 questions — not a clinically meaningful
  measurement).

**Do not use any output to inform a diagnosis, treatment, dosage, or triage decision.**
If you deploy any interface on top of this, surface that disclaimer to the end user.

---

## 3. HOW TO READ THE HEADLINE RESULT HONESTLY

The paper's standout claim: **81.2% on the Med-HALT NOTA test, +11.71 pts over the 7B
baseline, exceeding the reported 70B baseline.** All true *as stated for that test*. But
the test and the metric matter enormously:

- **Med-HALT NOTA** = multiple-choice questions where the correct answer is *always*
  "None of the Above." A model biased toward **abstaining / refusing / "I do not know"**
  scores high **without any medical reasoning.** The system's prompt (Appendix Table 4)
  *explicitly* instructs the model to answer "I do not know" when unsure and to act as a
  cautious ethical assistant — i.e. it is tuned toward exactly the behavior NOTA rewards.
- Corroborating evidence from the paper's own Table 1:
  - GPT-3.5 scored **27.64** on NOTA but **49.10** on MedMCQA (real knowledge).
  - Llama-2-7B scored **69.49** on NOTA but **25.01** (chance) on MedMCQA.
  - The small models "win" on NOTA precisely because they abstain more, not because they
    know more.
- **The same final system scored 25.18% on MedMCQA — statistically identical to random
  guessing (4-choice ≈ 25%).** The paper states this plainly: the system "did not enhance
  general medical knowledge."

**Honest one-line framing:** *"RAG + dynamic adapter swapping improved the model's tendency
to abstain on unanswerable/fabricated questions; it did not improve medical knowledge or
reasoning."* Do not let the 81.2% number travel without that sentence attached.

## 4. THE ADAPTER SELECTION WAS AN ORACLE

In the paper, the adapter for each question was chosen using the **ground-truth category
label shipped with MedMCQA** (and chosen **at random** for Med-HALT FAKE, which has no
categories). There was **no learned category classifier** — the paper lists that as future
work ("a category identification method that selects the optimal adapter based on the
language in the question").

Consequences:
- The reported DAS results assume a **perfect router you will not have at inference time**
  on real, unlabeled questions.
- `adapters/selector.py` therefore ships an `OracleSelector` (reproduces the paper) **and**
  a `ClassifierSelector` **stub** (what a real deployment needs). Any claim about deployed
  performance must use the classifier path, not the oracle.

## 5. EVALUATION INTEGRITY CAVEATS

- The model was asked to emit JSON `{"cop", "cop index", "why correct"}` but **frequently
  did not**, so the paper used "a mixture of text processing techniques and manual review."
  `parsing.py` implements a best-effort robust parser, but **any automated score here is a
  reconstruction, not the paper's exact pipeline.** Log raw outputs and report parse-failure
  rates alongside accuracy.
- Retrieval latency was ~23s/query on the M2. Full-dataset evaluation is slow by design.
- The knowledge base was intentionally built on PubMed abstracts *not* specific to MedMCQA /
  Med-HALT to limit leakage — preserve that property if you rebuild the KB.

## 7. COMPUTE & ENVIRONMENT

- The paper ran entirely on an **Apple M2 Pro, 16 GB, 8-core GPU**, using **Apple MLX**
  because `bitsandbytes` does not support Apple Silicon. The MLX backend is primary here.
- Memory budget that made it fit: quantized base ≈ **3.98 GiB**, one fused adapter at a time
  keeps the live system **< 5 GiB**. **Fusing all 21 adapters simultaneously ≈ 84 GiB —
  do not do this.** Swap one adapter per inference.
- The `torch_backend.py` path (CUDA + bitsandbytes) is a portability stub and has **not**
  been reconciled with the paper's numbers.
