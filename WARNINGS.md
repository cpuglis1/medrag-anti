# ⚠️ WARNINGS

## 1. Not for clinical, diagnostic, or patient use

This is a **research proof-of-concept, not a medical device.** It has no regulatory clearance
and was never validated against clinical outcomes. Its outputs are generated by a small (7B)
local model over a static PubMed snapshot and can be wrong or incomplete.

**Do not use any output to inform a diagnosis, treatment, dosage, or triage decision.** If you
build an interface on top of this, surface that disclaimer to the end user.

## 2. Reconstruction, not the original code

This repo was rebuilt from the paper (the original implementation was lost). The model/data
code — MLX + Torch backends, BioMedLM embedder, FAISS KB build, QLoRA training, dataset
loaders — is fully implemented but has **not been run end-to-end** here: Llama-2 is gated and
a full run needs ~18 GB of downloads plus hours of on-device compute. It targets the
`mlx-lm` / `transformers` / `datasets` / `faiss` APIs as of early 2026, so **pin your
versions** and expect to adjust a call or two on first run. The Med-HALT HF dataset
ids/fields are marked `VERIFY` in `evaluation/datasets.py` and fail loudly if they don't
match. Values the paper didn't specify (cosine threshold `t`, LoRA rank/alpha, LR) are marked
`PAPER UNSPECIFIED` in `configs/default.yaml`.

## 3. No weights or datasets are shipped — respect upstream licenses

This repo contains no weights and no datasets. Before downloading anything, confirm you are
entitled to use it under its own terms:

| Asset | Source | Note |
|---|---|---|
| Llama-2-7B | Meta | Accept Meta's Llama-2 Community License (gated on HF). |
| BioMedLM (2.7B) | `stanford-crfm/BioMedLM` | Check model card license. |
| MedMCQA | `openlifescienceai/medmcqa` | Dataset license on HF. |
| Med-HALT | Pal et al. 2023 (arXiv:2307.15343) | Check dataset terms. |
| PubMed abstracts | TF `scientific_papers` (pubmed) | PubMed/NCBI usage terms. |

Don't commit weights, FAISS indexes, API keys, or downloaded corpora (see `.gitignore`).

## 4. Compute & memory

The paper ran on an **Apple M2 Pro (16 GB, 8-core GPU)** using **MLX** (bitsandbytes has no
Apple-Silicon support), so MLX is the primary backend. Quantized base ≈ **3.98 GiB**; fusing
one adapter at a time keeps the live system **< 5 GiB**. **Fuse one adapter per inference —
loading all 21 at once ≈ 84 GiB.** The torch/CUDA path is an alternative and hasn't been
reconciled with the paper's numbers.
